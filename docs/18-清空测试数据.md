## 二、清理命令

```bash
pnpm db:clean:content --dry    # 先看会删什么
pnpm db:clean:content          # 真删
```

它做的顺序（先子表后主表，避免外键报错）：

```
favorites → reports → download_events → resource_tags
→ resource_links → submissions → resources
→ 重置自增序列 → tags.use_count 归零 → 重建搜索索引
```

**保留**：`categories`（7 个）、`tags`（12 个）、`users`（1 个管理员）。
分类和标签是你的骨架，不该跟着内容一起清。

| resource_links | 443 |

## 四、重要：清空后哪些验收脚本跑不过

有 7 个 e2e 依赖"库里有内容"，本地清空后会红：

| 脚本 | 依赖 |
|---|---|
| `test-auth` | 首页要有可点开的资源卡 |
| `test-pagination` | 至少 24 条才出第二页 |
| `test-report` | `/r/excel-dashboard-pack` 要存在 |
| `test-admin-tools` | 资源列表要有行 |
| `test-import` | 能跑，但断言"新增 2 条"会污染空库 |
| `test-seo` | 详情页要存在 |
| `test-submit` | 能跑，会留下投稿/草稿 |

**CI 不受影响**：workflow 里每次都先 `db:migrate && db:seed && seed:bulk --count 60` 再跑，
自带一套数据。所以本地空库 + CI 绿是可以同时成立的。

本地想复现 CI 状态：

```bash
pnpm db:seed            # 24 条种子
pnpm seed:bulk --count 60
pnpm covers:gen
```

再清一次：`pnpm seed:bulk --clean && pnpm db:clean:content`。

## 五、导入自己的数据时

```bash
# 1. 把链接整理成一行一个
notepad links.txt

# 2. 生成 CSV（自动识别网盘、抓标题、猜提取码）
pnpm import:links links.txt --cat template

# 3. 打开 data/import/batch.csv 检查标题与分类

# 4. 后台 → 批量导入 → 粘贴 → 开始导入
#    （导入后自动生成编号、状态=已发布、重建搜索索引）

# 5. 跑一次巡检确认没有死链
pnpm links:check
```

注意：**导入的资源状态是「已发布」**，会立刻出现在前台。想先审一遍就在后台把状态改成草稿。
