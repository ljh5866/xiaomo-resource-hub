# 14 · 投稿入口与举报自动降权

> 日期：2026-11-03 ｜ 状态：游客可投稿 → 后台采纳生成草稿；同一链接被举报满 3 次自动标失效

---

## 一、投稿链路

```
/submit（免登录表单）
   ↓ POST /api/submit   ← 限流 3 次/小时/IP，URL 格式与网盘类型白名单
submissions 表（status=pending，同 URL 去重）
   ↓
/admin/submissions：待审优先
   ├ 采纳并建草稿 → 生成 status=draft 的资源 + 一条主链接（source_note=读者投稿 #id）
   └ 拒绝
```

| 件 | 位置 |
|---|---|
| 表单 | `src/components/submit/submit-form.tsx` |
| 页面 | `src/app/submit/page.tsx`（页脚有入口） |
| 接口 | `src/app/api/submit/route.ts` |
| 后台 | `src/app/admin/submissions/page.tsx` |
| 动作 | `acceptSubmission` / `rejectSubmission`（均带 `guard()`） |
| 表 | `src/db/sql/004_submissions.sql` |

**采纳只生成草稿，不直接发布**——投稿质量参差，发布这一步必须留人工。
草稿里 `source_note` 记了「读者投稿 #12」，方便回溯。

去重规则：同一 URL 且状态是 `pending`/`accepted` 时不再入库，前端提示「这条已经投过了」。

## 二、举报自动降权

之前举报只是攒在后台，得人工去点。现在加了一条确定性规则：

```
同一 link_id 的 open 举报数 ≥ 3
    → resource_links.status = 'invalid'
    → checked_at = now，fail_count = 举报数
    → 前台该链接立刻变「失效」（详情页降权、卡片状态点变红）
```

实现位置：`src/app/api/report/route.ts` 插入举报后立刻统计。

**为什么按 link 而不是按 resource**：一个资源常有多条网盘链接，夸克挂了不代表百度也挂了。
按链接粒度降权，用户还能看到其他可用链接。

**为什么是 3 次**：单次举报误报率高（用户自己网络问题、提取码过期没看说明）。
3 次是"多人独立遇到同一问题"的最低信号量。可在后台调整为 2 或 5。

## 四、这一轮踩的坑

`PROVIDERS` 不是 `Record<string, string>`，而是 `Record<ProviderKey, { name, short, tint }>`。
表单里直接 `Object.entries(PROVIDERS).map(([k, label]) => <option>{label}</option>)`
把对象当 ReactNode 渲染，构建期报 `Type '{ name… }' is not assignable to ReactNode`。

顺带把举报弹窗里的链接下拉从「quark」改成「夸克网盘」——同一份常量，两处受益。

### 验收脚本自己的两个不幂等

跑第二遍就红，两次都不是产品 bug，是脚本的问题：

1. **限流测试锁了管理员**。原来用 admin 账号连输 6 次错密码，把 admin 锁 10 分钟，
   下一次跑测试连登录都过不去。改成用 `ratelimit-guard@xiaomo.local`（不存在的账号）——
   同样能触发限流，但不影响真账号。
2. **用行数判断有没有删**。流式渲染期间 `tbody tr` 会短暂出现两份（200 → 400），
   `rowsBefore === rowsAfter` 必然不等。改成判断「第一行的标题还在不在 + 弹窗关没关」，
   语义也更贴近要验证的东西。

> 教训：验收脚本要能连续跑，否则 CI 绿一次不代表下一次还绿。
