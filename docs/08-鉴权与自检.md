## 一、做了什么

| 件 | 实现 |
|---|---|
| 登录 | `/login`：邮箱 + 密码，NextAuth v5 Credentials，JWT 会话（30 天） |
| 密码存储 | `scrypt`（Node 内置），格式 `scrypt$N$salt$hash`，见 `src/lib/password.ts` |
| 后台保护 | `src/middleware.ts` 拦 `/admin/*` → 302 `/login?next=…`；`admin/layout.tsx` 再校验一次（纵深防御） |
| 账号创建 | `pnpm user:add <email> <password> [--admin]`（无自助注册） |
| 退出 | `/api/logout`：删会话 cookie 后回首页（不用 next-auth 的 signOut，原因见下） |
| 收藏 | 登录 → 写 `favorites` 表；游客 → 写 cookie。`GET /api/favorite?id=` 查状态 |
| 上传 | `/api/upload` 仅管理员，未登录返回 401 |
| 会话展示 | 头部改为客户端 `UserMenu`（`useSession`），服务端页面不再被 cookie 拖成动态 |

### 账号怎么用

```bash
pnpm user:add admin@xiaomo.local xiaomo2026 --admin   # 管理员
pnpm user:add reader@example.com reader2026           # 普通用户
```

管理员能进 `/admin`，普通用户只能收藏。

## 二、三个"从文档里查不到"的坑

### 1. next-auth 的 `signOut()` 放在 Server Action 里，Set-Cookie 会丢

现象：点退出 → 跳到首页了，但会话 cookie 还在，再访问 `/admin` 依旧是登录态。
根因：Server Action 的流式响应里，Set-Cookie 有时不落到最终响应。
解法：自己写 `/api/logout`，显式 `cookies().delete()`。

### 2. 用裸 `new Response()` 返回，cookie 删除不生效

现象：`cookies().delete()` 调了，响应里却没有 `Set-Cookie`。
根因：Next 只把 cookie 变更附加到 **NextResponse** 实例上，裸 Response 走的是另一条路。
解法：`const res = new NextResponse(null, { status: 303 })`，再手动设 `Location`。

### 3. `NextResponse.redirect(new URL("/", req.url))` 会把 host 换成 localhost

现象：从 `127.0.0.1:3100` 退出后被送到 `localhost:3100`，跨源，旧 cookie 看起来"没删掉"。
解法：响应里写**相对** `Location: /`，让浏览器保持当前源。

> 这三条合起来就是一句话：**退出登录看起来最简单，其实最容易半死不活。** 所以它必须进 e2e。

## 三、顺手修掉的缓存退化

把 `auth()` 放进 Header 后，整站变成动态渲染（首页从 ISR 掉成 ƒ）。
处理：

1. 会话状态移到客户端 `UserMenu`（`useSession`），服务端不再读 cookie；
2. 详情页的收藏状态改成客户端 `GET /api/favorite?id=…`，服务端不碰 cookie；
3. 分类页的平台筛选改成客户端过滤（URL 仍是唯一状态源），页面本身可静态化；
4. 给 `/r/[slug]`、`/c/[category]`、`/t/[tag]` 补 `generateStaticParams`。

结果（`next build` 路由表）：

```
○ /                    10m      ← 静态
● /c/template          10m      ← SSG（7 个分类）
● /r/excel-dashboard-pack 1h    ← SSG（24 条资源）
● /t/excel             1h       ← SSG（17 个标签）
ƒ /admin /search /favorites /login /api/* /files/* /go/*
```

## 四、数据库迁移器换掉了 drizzle-kit push

`drizzle-kit push` 会把手工建的 FTS5 虚表当成"多余的表"删除，还只删一半（`resources_fts_data` 报 `no such table`），把库搞成半残。

现在改成显式 SQL 迁移：

```
src/db/sql/001_init.sql        # 全量建表（IF NOT EXISTS）
src/db/sql/002_user_password.sql
scripts/migrate.mjs            # 按文件名顺序执行，已应用的记在 _migrations
pnpm db:migrate                # 只跑迁移
pnpm db:push                   # 迁移 + 重建索引（保留旧命令名）
```

好处：迁移只做我们写下来的事，不会再误删搜索索引；坏处：schema.ts 与 SQL 需要人工保持一致（已在文件头注明）。

## 六、还没做的

| # | 项 | 风险 |
|---|---|---|
| 1 | 无注册 / 找回密码 | 用户只能找站长开号；现阶段可接受 |
| 2 | 登录无频率限制 | 暴力破解可行，上线前加「同 IP 5 次/分钟」 |
| 3 | JWT 无法服务端吊销 | 改密码后旧 token 仍有效到过期；需要黑名单表 |
| 4 | 游客收藏不并入账号 | 登录后要重新收藏一次 |
| 5 | 权限只区分 admin/user | 没有编辑、审核角色 |
