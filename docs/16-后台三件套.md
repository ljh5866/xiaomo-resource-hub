## 一、为什么先做这三个

内容只有 24 条时，后台的把问题都藏着：

| 症状 | 到 227 条时 |
|---|---|
| 资源列表一次渲染全部 | 一屏 200+ 行，找不到东西 |
| 分类和标签写死在 seed 里 | 想加一个分类得改代码、重跑种子 |
| 巡检只能看不能动 | 发现链接失效，得开命令行跑脚本 |

这三件都不是"新功能"，是**把已有功能补到能用**。

## 二、1. 资源列表：搜索 + 分页

```
/admin/resources?q=Excel&status=published&page=2
```

- 搜索范围：标题 / 编号 / 副标题 / slug —— 后台最常发生的是"我记得编号 XM-2026-0034"
- 分页：30 条/页，`LIMIT ? OFFSET ?`，总数单独 `COUNT(*)`
- 状态标签与搜索条件**互相保留**（切 tab 不丢关键词，搜索不丢 tab）

实现上把 where 拼装抽成 `buildWhere(q, status)`，两个查询共用同一份条件，
避免"列表查的和计数查的不是一件事"这种经典错位。

---

## 三、2. 分类与标签管理

`/admin/taxonomy` 一页两个区：

**分类**：改名、排序值、前台可见开关。排序值小的排前面（对应 `sort_order`）。
关掉"前台可见"后，分类页仍可直达，但分类栏不再出现——留了后路，不至于误删。

**标签**：改名、合并、删除。

- **合并**是重点：`INSERT OR IGNORE` 搬关系 → 删旧关系 → 删标签 → 重算 `use_count`。
  `OR IGNORE` 是关键，否则"某资源同时挂 A、B 两个标签"时会撞主键。
- **删除受保护**：还有资源在用就拒绝，提示"先合并再删"。这比级联删除安全。

## 四、3. 巡检：一键复测

把 `check-links.ts` 里的探测逻辑抽成 `src/lib/link-check.ts`，
命令行的 `pnpm links:check` 和后台的按钮走**同一份实现**（避免两份逻辑漂移）。

```
POST /api/admin/recheck-links { limit: 20 }   ← 需管理员
    → checkLinks({ limit, statuses: ["unknown","invalid"] })
    → 返回 { checked, okCount, invalid, unknown, skipped }
```

按钮只测「待校验 / 失效」的链接，默认 20 条 —— 一次请求里跑太多会被超时打断。
命令行仍然是全量（`--limit 200`）。

## 五、这一轮踩的坑

### 1. `revalidatePath` 在 Server Action 里也能炸

现象：表单提交后没反应，服务端日志：

```
Error: Route "/admin/taxonomy": `revalidatePath("/admin/taxonomy")` can't be called during render.
```

原因：这组表单动作挂在 `force-dynamic` 页面上，Next 在 RSC 渲染期间就把它判成
"render 期间调用 revalidate"，直接抛。

修法：**后台页本来就不缓存，不需要 revalidate**。把它从动作里删掉，
前台（首页/分类）交给 ISR 自然过期。如果确实要即时刷新前台，应该放到
Route Handler 里调，而不是 Server Action。

### 2. 测试用 `hasText` 定位行，命中了所有行

标签合并测试一直"失败"，实际是**测试选错了行**：

```js
page.locator("div.border", { hasText: "macOS" })   // ← 命中 15 行
```

因为每个标签行的「合并到…」下拉里都列着所有标签名，包括 "macOS"。
于是测试把别的标签合进去了（顺带把 demo 标签从 18 个合成 14 个）。

修法：按「改名输入框的 value」精确匹配：

```js
for (let i = 0; i < rowCount; i++) {
  if (await rows.nth(i).locator('input[name="name"]').inputValue() === from.name) { … }
}
```

> 教训：定位器不能依赖"页面上唯一会出现某文字"这种假设，下拉选项就是经典反例。
