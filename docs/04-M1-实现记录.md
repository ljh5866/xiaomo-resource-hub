## 三、过程中改掉的一个技术决策（重要）

**原计划**：Drizzle + better-sqlite3 作为运行时 ORM。

**实际**：better-sqlite3 在 Node 24.19 + Next 16 下不可用——原生 `Statement` 析构发生在 env teardown 之后，触发

```
Assertion failed: (env) != nullptr  →  exit code 134 (SIGABRT)
```

start 后第一个请求就崩，dev/start 都一样。

**处理**：

| 层 | 方案 |
|---|---|
| 运行时查询 | 改用 Node 24 内建 **`node:sqlite`（DatabaseSync）**，零原生扩展、零编译依赖 |
| 迁移 / 种子 | 仍用 `drizzle-kit push` + `better-sqlite3`（脚本进程跑完即退，不常驻，不崩） |
| 访问层 | `src/db/client.ts` 提供 `all / get / run / ts`，惰性开库 + 失败降级（查询失败返回空而不是 500） |

**收益**：部署机不再需要 VS Build Tools / node-gyp；构建期多 worker 并发开库也不会互相拖死。

**代价**：`src/lib/queries.ts` 是手写 SQL（原计划用 Drizzle Query Builder）。SQL 都是单表/两表 JOIN，可读性没问题，反而更容易加索引提示。

> 这段记下来的原因：下一个接手的人不该再踩一次。

| 项 | 内容 |
|---|---|
| 分词 | `src/lib/search/tokenize.ts`：中文 2-gram + 英文整词，**纯 JS 零依赖**（吸取 better-sqlite3 的教训，不再引原生扩展） |
| 索引 | `resources_fts`（FTS5，两列 `title_tokens` / `body_tokens`），`resource_id` 不索引 |
| 排序 | `bm25(fts, 8.0, 1.0)` —— 标题命中权重是正文的 8 倍 |
| 过滤 | OR 召回后按 token 覆盖度丢弃噪声（查询 ≥3 token 时要求命中 ≥1/3） |
| 兜底 | 索引为空或 0 命中 → 自动回落 SQL LIKE |
| 维护 | `pnpm db:reindex` 重建；`db:seed` 结束会自动建索引 |
