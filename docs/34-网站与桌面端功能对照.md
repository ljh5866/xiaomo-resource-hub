# 34 · 网站功能 ↔ 桌面端移植对照

> 桌面端现状：`desktop/`（Tauri 2），只做了**只读浏览**。
> 本文按网站实际页面清单逐项对照，不凭印象。

## 一、网站有什么（实测清单）

前台页面 16 个：首页、`/c/[category]`、`/t/[tag]`、`/r/[slug]`、`/search`、`/favorites`、
`/login`、`/register`、`/me`、`/me/settings`、`/me/pan`、`/parse/[id]`、`/submit`、`/updates`、`/about`、`/styleguide`。

API 27 个：`app/*`（桌面端用）、`auth/*`、`favorite`、`report`、`submit`、`resources`、`me`、
`avatar`、`upload`、`github/*`、`pan/*`（解析/取链/下载/扫码/绑定）、`soft/download`、`og`、`health`、`logout`、`admin/recheck-links`。

## 二、对照表

| 网站功能 | 桌面端 | 说明 |
|---|---|---|
| **首页**（最新上架、分类入口） | ✅ 有 | 侧栏分类 + 卡片流，效果等价 |
| **分类页** `/c/x`（筛选 + 分页） | 🟡 部分 | 筛选有（分类+标签）；**分页只有「加载更多」**，不能跳页 |
| **标签页** `/t/[tag]` | ✅ 有 | 侧栏标签点击等价 |
| **资源详情** `/r/[slug]` | 🟡 部分 | 正文/标签/链接/meta 有；**少了举报、收藏、相关推荐、分享** |
| **搜索** `/search` | 🟡 部分 | 有搜索框，但走 **SQL LIKE**，不是网站的 FTS5 中文分词；无结果分页、无关键词高亮 |
| **收藏列表** `/favorites` | ❌ 没有 | 需要账号体系，桌面端无登录 |
| **登录 / 注册** | ❌ 没有 | 无账号概念 |
| **个人中心** `/me` | ❌ 没有 | — |
| **设置** `/me/settings` | ❌ 没有 | 桌面端连自己的设置页都没有（API 基址只能改 localStorage） |
| **网盘绑定** `/me/pan` | ❌ 没有 | 依赖浏览器扩展策略，桌面端无对应形态 |
| **站内解析** `/parse/[id]` | ❌ **没有** | **这是网站最核心的能力**：解析分享目录、转存、取直链、多连接下载 |
| **投稿** `/submit` | ❌ 没有 | 需要在桌面端写长表单，价值不大 |
| **举报** | ❌ 没有 | 详情页缺入口 |
| **更新日志** `/updates` | ❌ 没有 | 可做「检查更新」页 |
| **关于** `/about` | ❌ 没有 | — |
| **GitHub Trending**（`/c/opensource?hot=1`） | ❌ 没有 | 未接 |
| **精选题**（`is_featured`） | ❌ 没有 | 未接 |
| **后台** `/admin/*` | ⛔ 不该移植 | 运营用，桌面端不需要 |
| **SEO / OG 图** | ⛔ 不需要 | 桌面端没有 SEO 概念 |

## 三、统计

| 状态 | 数量 | 占比（不含后台/SEO） |
|---|---|---|
| ✅ 完整移植 | 3 | 首页、标签、API 层 |
| 🟡 部分移植 | 3 | 分类、详情、搜索 |
| ❌ 未移植 | 11 | 收藏、登录、个人中心、设置、网盘绑定、**站内解析**、投稿、举报、更新日志、关于、Trending |

**结论：桌面端目前只移植了「看」的部分，占网站功能约 25%。**

## 四、缺口里哪些该补

### 必补（决定桌面端是不是「能用」的工具）

| # | 功能 | 理由 | 工作量 |
|---|---|---|---|
| 1 | **站内网盘解析 + 下载** | 网站的核心价值；桌面端做这件事比网页强得多（无跨域、可多连接、可断点续传到本地） | **3–4 天** |
| 2 | **本地收藏 + 历史** | 不需要账号，本地 SQLite 即可；桌面端最该有的功能 | 半天 |
| 3 | **设置页** | API 基址、主题、清缓存、检查更新 | 2 小时 |
| 4 | **排序 + 分页跳转** | 1043 条没有排序很难用 | 3 小时 |

### 选补

| # | 功能 | 理由 | 工作量 |
|---|---|---|---|
| 5 | 举报 | 详情页一行入口，直接 POST `/api/report` | 1 小时 |
| 6 | GitHub Trending | 独立的第二视图 | 半天 |
| 7 | 精选题 | 首页加一块 | 2 小时 |
| 8 | 更新日志 / 关于 | 设置页里的子页 | 1 小时 |

### 不该补

| 功能 | 原因 |
|---|---|
| 登录 / 注册 / 个人中心 | 桌面端定位是「本地资源浏览器」，不背账号体系；要收藏同步时再单独做 token 登录 |
| 网盘绑定（扩展那套） | 桌面端能直接读本机浏览器 cookie，不需要扩展——但那是另一套实现 |
| 投稿 | 长表单在桌面端体验差，网站更合适 |
| 后台 | 运营功能 |

## 五、桌面端独有的机会（网站做不到）

这几件事是桌面端**比网站强**的地方，也是移植时应该顺手做掉的：

| 能力 | 说明 |
|---|---|
| **本机浏览器 cookie 读取** | Windows 上读 Chrome/Edge 的 Cookies（DPAPI 解密），直接拿到夸克登录态，用户零操作 |
| **多连接 Range 下载到本地** | 不受服务器带宽限制，用户网络直连网盘，512 线程那是云析的量级 |
| **断点续传到本地文件** | 浏览器只能整包下载 |
| **全局快捷键唤起** | `Ctrl+Shift+X` |
| **剪贴板识别** | 复制网盘链接自动建资源 |
| **托盘常驻** | 已做 |

## 六、一句话结论

**移植了「浏览」，没移植「用」。**
要看内容、筛、搜、跳网盘——都行；要收藏、下载到本地、用站内解析——还都没有。
补完第 4 节「必补」的四项，桌面端才算和网站功能对等；再加上第五节那些，才是网站做不到的形态。
