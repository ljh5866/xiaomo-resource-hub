# 02 · 技术架构与数据模型

> 设计原则一句话：**一个人能维护，一台机器能跑起来，坏了能在 30 分钟内恢复。**

---

## 一、技术选型与理由

### 选型表

| 层 | 选型 | 版本 | 为什么是它（而不是别的） |
|---|---|---|---|
| 框架 | **Next.js**（App Router，RSC） | 16.x | 一个进程同时给 SSR 页面、API、cron 入口；ISR 让详情页近乎静态，SEO 友好 |
| 语言 | **TypeScript** | 5.x | 数据模型复杂（多链接、状态机），类型是护栏 |
| 样式 | **Tailwind CSS v4** | 4.x | 配合 DESIGN.md 的 token 体系，避免 CSS 打架；v4 的 `@theme` 直接映射设计变量 |
| 组件 | **shadcn/ui 风格手写原语**（Radix primitives） | — | 代码在自己仓库里，可改成任何样子；不引整包组件库 |
| ORM | **Drizzle ORM** | 最新 | 类型即 schema、迁移文件可读、无重客户端（对比 Prisma 的引擎体积） |
| 数据库 | 本地 **SQLite**（better-sqlite3）→ 生产 **PostgreSQL 16** | — | 同一套 schema 两种方言，Drizzle 支持；本地零依赖起步 |
| 搜索 | MVP：**SQLite FTS5 + jieba 切词**；V1：**Meilisearch** | — | FTS5 内置零成本；中文靠切词解决分词；量大再换 |
| 鉴权 | **Auth.js v5**（Credentials + Email OTP） | 5.x | 单管理员起步，后续接微信/QQ 有现成 provider |
| 校验 | **Zod** | 4.x | 表单、API、导入三处共用一套 schema |
| 内容渲染 | **Markdown → MDX**（`next-mdx-remote` 或 `@next/mdx`） | — | 资源说明需要富文本但不需要富文本编辑器 |
| 图片 | **sharp** + 对象存储（R2/OSS） | — | 封面自动转 WebP/AVIF，尺寸收敛 |
| 部署 | **VPS + Caddy + systemd** | — | 比 Vercel 更适合国内访问控制与成本；Caddy 自动 HTTPS |
| 监控 | UptimeRobot + 自建 `/api/health` + 结构化日志 | — | 够用，不引 Sentry |

### 被否掉的方案

| 方案 | 否决理由 |
|---|---|
| WordPress + RiPro/JustNews 主题 | 需要 PHP（本机没有）；主题闭源/授权复杂；SEO 插件臃肿；性能天花板低 |
| 苹果CMS | PHP 栈 + 采集导向，与"人工策展"定位相悖 |
| Astro（qiyuan 模板同款） | 静态优先很适合内容站，但后台 CRUD、巡检、用户系统要另起一套，总组件数更多 |
| Nuxt3 + Go（urldb 同款） | 两套语言两套部署，单人维护成本翻倍 |
| Supabase / Firebase | 数据出境 + 国内访问质量不可控 |
| 直接 fork urldb | GPL v3，衍生作品需开源；且它是"工具"不是"品牌站" |

## 二、系统架构

```

│                         浏览器 / 爬虫                          │
└───────────────────────────┬──────────────────────────────────┘
                            │ HTTPS
┌───────────────────────────▼──────────────────────────────────┐
│                     Caddy (反代 + 自动证书)                    │
└───────────────────────────┬──────────────────────────────────┘
                            │ :3000
┌───────────────────────────▼──────────────────────────────────┐
│                    Next.js 16 (单进程)                        │
│  ┌────────────┬────────────┬────────────┬─────────────────┐  │
│  │  RSC 页面   │  Route     │  Server    │  /admin 后台    │  │
│  │  (SSR/ISR) │  Handlers  │  Actions   │  (Server Comp.) │  │
│  └─────┬──────┴─────┬──────┴─────┬──────┴────────┬────────┘  │
│        │            │            │               │           │
│  ┌─────▼────────────▼────────────▼───────────────▼────────┐  │
│  │            领域层 lib/ (纯函数 + Zod schema)             │  │
│  │  search · links · resources · categories · auth        │  │
│  └─────┬──────────────────────────────────┬───────────────┘  │
└────────┼──────────────────────────────────┼──────────────────┘
         │                                  │
┌────────▼─────────┐              ┌─────────▼──────────────┐
│  SQLite / PG     │              │  对象存储 (R2 / OSS)    │
│  + FTS5 索引     │              │  封面图 / 备份 / 静态   │
└────────▲─────────┘              └────────────────────────┘
         │
┌────────┴──────────────────────────────────────────────────┐
│  后台定时任务（node-cron 或 systemd timer）                 │
│  · 链接巡检 link-checker  (每日 03:00)                     │
│  · 搜索索引重建 reindex   (资源变更后 5min 防抖)            │
│  · 数据库备份 backup      (每日 04:00 → 对象存储)           │
└────────────────────────────────────────────────────────────┘
```

**为什么全塞一个进程**：单人维护下，每多一个进程就多一个半夜会挂的东西。cron 用 `node-cron` 跑在 Next.js 的自定义 server 或独立 `scripts/worker.ts`（推荐后者，避免阻塞请求）。

## 四、数据模型

### 4.1 实体关系

```
categories 1──n resources
resources 1──n resource_links     （一个资源多网盘 / 多版本）
resources n──n tags (resource_tags)
users     1──n favorites
users     1──n download_events
resources 1──n reports            （失效举报）
```

### 4.2 表定义（Drizzle 风格伪代码，M1 直接落地）

```ts
// ---------- 分类 ----------
categories {
  id          serial pk
  slug        text unique          // 'software' | 'template' | 'material'
  name        text                 // '软件工具'
  description text
  icon        text                 // lucide icon name，不用 emoji
  sort_order  int   default 0
  is_visible  bool  default true
}

// ---------- 资源（核心表） ----------
resources {
  id            serial pk
  code          text unique        // 'XM-2026-0417' 目录编号（可引用）
  slug          text unique        // 'excel-dashboard-template-pack'
  title         text not null      // 'Excel 数据看板模板合集'
  subtitle      text               // 一句话副标题（卡片第二行）
  summary       text               // 120 字内摘要（列表/SEO description）
  content_md    text               // 详情页正文（Markdown，≥150 字原创）

  category_id   int  fk → categories.id
  kind          text               // 'software'|'template'|'material'|'course'|'ebook'|'font'|'icon'|'other'
  platform      text[]             // ['windows','mac','web','android','ios'] 多选
  version       text               // 'v2.4.1' 或 null
  size_label    text               // '1.2 GB'（展示用字符串，不存字节）
  language      text               // 'zh-CN'|'en'|'multi'
  license_label text               // '免费'|'开源'|'试用'|'需授权'

  cover_url     text
  cover_blur    text               // base64 缩略，做 LQIP 防抖动

  source_url    text               // 来源页（台账，见运营）
  source_note   text               // 来源说明 / 授权形式
  verified_at   timestamp          // 最近一次人工确认有效

  status        text default 'draft'  // 'draft'|'published'|'archived'
  is_featured   bool default false
  view_count    int  default 0
  download_count int default 0
  favorite_count int default 0

  seo_title     text
  seo_desc      text

  published_at  timestamp
  created_at    timestamp default now
  updated_at    timestamp default now

  // 索引
  index (category_id, status, published_at desc)
  index (updated_at desc)
}

// ---------- 下载链接（资源站的生命线） ----------
resource_links {
  id            serial pk
  resource_id   int fk → resources.id  (on delete cascade)
  provider      text not null   // 'baidu'|'quark'|'aliyun'|'xunlei'|'123'|'uc'|'115'|'self'
  url           text not null
  url_hash      text not null   // sha256(url) 用于全站去重
  extract_code  text            // 提取码（明文展示，属于公开信息）
  label         text            // '主链接' | '备用' | 'Windows 版'
  is_primary   bool default false
  sort_order   int  default 0

  status        text default 'unknown'  // 'ok'|'invalid'|'unknown'|'checking'
  checked_at    timestamp
  fail_count    int  default 0
  last_error    text

  click_count   int  default 0
  created_at    timestamp default now

  unique (resource_id, url_hash)
  index (status, checked_at)
}

// ---------- 标签 ----------
tags { id, slug unique, name, use_count int }
resource_tags { resource_id, tag_id, primary key(resource_id, tag_id) }

// ---------- 用户与行为 ----------
users {
  id, email unique, name, avatar_url,
  role text default 'user',     // 'user'|'admin'
  created_at
}
favorites { user_id, resource_id, created_at, primary key(user_id, resource_id) }
download_events {
  id, resource_id, link_id, user_id nullable,
  ip_hash text,      // 不存明文 IP
  ua_family text, referer_host text,
  created_at
  index (resource_id, created_at desc)
}

// ---------- 举报 ----------
reports {
  id, resource_id, link_id nullable,
  reason text,          // 'link-dead'|'wrong-content'|'other'
  contact text,         // 可选
  status text default 'open',  // 'open'|'handled'|'rejected'
  created_at, handled_at
}

// ---------- 搜索索引（SQLite 专用） ----------
resource_fts (FTS5 虚拟表) {
  code, title, subtitle, summary, tokens   // tokens = jieba 切词后空格拼接
}
```

### 4.3 关键设计决策

| 决策 | 理由 |
|---|---|
| **`size_label` 存字符串不存字节** | 资源大小常是"约 1.2GB"这种模糊值，强转数字会丢信息且引发类型错误 |
| **`code` 独立于 `id`** | 目录编号要稳定、可读、可被外部引用（`XM-2026-0417`），不随自增 id 变化 |
| **`url_hash` 做唯一约束** | 全站同一条网盘链接只能属于一个资源，从源头防重复 |
| **`status` 用四态而非布尔** | `unknown` 与 `invalid` 必须分开：新链接还没测过 ≠ 已经挂了 |
| **不存明文 IP** | 只存 `ip_hash`，统计去重够用，减少数据敏感度 |
| **`fail_count` 连续失败才判死** | 单次超时（尤其百度网盘）不等于失效，避免误杀 |

## 五、搜索实现

### 阶段一：SQLite FTS5 + jieba（MVP）

中文 FTS5 的坑：默认 `unicode61` 分词器会把整句中文当一个 token，等于没分词。

**解法（三步）**：

```ts
// 1. 入库时切词
import { cut } from '@node-rs/jieba'            // 或 nodejieba
const tokens = cut(`${title} ${subtitle} ${summary} ${tags.join(' ')}`, true)
  .filter(t => t.trim().length > 0)
  .join(' ')
// 写入 resource_fts.tokens

// 2. 查询时同样切词
const q = cut(keyword, true).map(t => `"${t}"*`).join(' OR ')

// 3. 排序：bm25 + 人工权重
SELECT r.*, bm25(resource_fts, 10.0, 6.0, 3.0, 1.0) AS rank
FROM resource_fts
JOIN resources r ON r.code = resource_fts.code
WHERE resource_fts MATCH ? AND r.status = 'published'
ORDER BY rank ASC, r.download_count DESC
LIMIT 20;
```

**排序权重设计**（第一列是最重要的）：`title 10 / subtitle 6 / summary 3 / tokens 1`，再叠加「下载量 + 新鲜度」的小幅加成。

### 阶段二：Meilisearch（资源量 > 5,000 或搜索 QPS 上来后）

- 自带 charabia 中文分词，不用自己切
- 支持 typo 容错、同义词、分面统计（这里直接产出筛选器计数）
- 同步方式：资源变更 → 写 `outbox` 表 → worker 批量 push

**触发切换的量化条件**：搜索 P95 > 300ms，或需要"输入即搜"的联想。

## 六、链接巡检状态机

这是整个项目最容易被低估、却最决定口碑的部分。

```
        上架/新增
           │
           ▼
      ┌─────────┐   探测成功   ┌──────┐
      │ unknown ├─────────────►│  ok  │
      └────┬────┘              └──┬───┘
           │ 探测失败             │ 探测失败
           ▼                      ▼
      fail_count += 1        fail_count += 1
           │                      │
     fail_count ≥ 3 ?        fail_count ≥ 2 ?
           │                      │
           ▼                      ▼
      ┌─────────┐            ┌─────────┐
      │ invalid │◄───────────┤ 降权展示 │
      └────┬────┘            └─────────┘
           │ 人工复核/举报后重测成功
           └──────────► ok (fail_count = 0)
```

**实现要点**

| 要点 | 做法 |
|---|---|
| 探测方式 | `fetch(url, { method:'GET', redirect:'follow', signal: AbortSignal.timeout(8000) })`，看 `res.status` + 页面关键词（"链接不存在"/"已失效"/"分享已取消"） |
| 频率 | 每日 03:00 全量；`ok` 的每 7 天一次，`unknown` 的每天一次，`invalid` 的每 30 天复查一次 |
| 并发 | 5 并发 + 每请求 300ms 间隔，避免被网盘风控 |
| 降权规则 | `invalid` 的链接**不隐藏**，但移到列表末尾并打灰标 + "小编正在修复" ← 比直接消失更让用户信任 |
| 通知 | 每日巡检报告写进 `/admin/links`，超过 20 条新失效时邮件告警 |

## 七、下载跳板 `/go/[id]`

所有下载都必须经过站内跳转，理由有三个：统计、防盗链、可替换。

```ts
// app/go/[id]/route.ts
export async function GET(req, { params }) {
  const link = await getLinkById(params.id)          // 含 resource 关系
  if (!link || link.status === 'invalid' && !allowInvalid) {
    return NextResponse.redirect('/r/' + slug + '?dead=1')
  }
  // 1. 异步记录（不阻塞跳转）
  after(() => recordDownload({ linkId, resourceId, ipHash, ua, referer }))
  // 2. 增量计数
  after(() => bumpCounters(link.resource_id, link.id))
  // 3. 302 到真实地址
  return Response.redirect(link.url, 302)
}
```

**反滥用**：同一 `ip_hash` 对同一 link 的计数 10 分钟内只算一次；`referer` 非本站时仍放行但单独记 `external`。

## 八、安全与运维清单

| 项 | 措施 |
|---|---|
| 鉴权 | 后台路径全部走 server-side session 校验，middleware 只做粗筛，真正校验在 layout + action 里 |
| CSRF | Server Actions 自带 origin 校验；REST 用 double-submit token |
| 输入 | 全部经 Zod；Markdown 渲染开启 sanitize（禁 raw HTML 或白名单） |
| 限流 | `/api/search` 与 `/api/report` 按 IP 滑动窗口（内存 Map 起步，多实例再上 Redis） |
| 备份 | 每日 `sqlite3 .backup` / `pg_dump` → 对象存储，保留 14 份；每月做一次**恢复演练** |
| 日志 | pino 结构化 JSON，`requestId` 贯穿；错误日志单独文件 + 轮转 |
| 健康检查 | `/api/health` 返回 DB 延迟 + 版本 + 队列积压 |
| 依赖 | `pnpm audit` 每周一次；锁定 lockfile |
| 上线流程 | `git tag` → CI 构建 → 蓝绿切换（pm2 reload，零停机） |

## 十、性能预算

| 指标 | 目标 | 手段 |
|---|---|---|
| LCP | < 2.0s（4G） | 封面图 AVIF + 固定宽高 + 首屏 Critical CSS |
| CLS | < 0.05 | 所有图片预留尺寸；字体 `display: swap` + 预加载首屏字体 |
| INP | < 200ms | 搜索用 `useDeferredValue`，筛选走 URL state 不做全量重渲染 |
| 详情页 TTFB | < 300ms | ISR（`revalidate = 3600`）+ 后台保存时 `revalidatePath` |
| 首屏 JS | < 120KB gzip | 列表页不留客户端组件；交互岛最小化 |
