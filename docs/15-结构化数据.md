# 15 · 结构化数据（JSON-LD）

> 日期：2026-11-03 ｜ 状态：站点级 / 列表页 / 详情页 / 面包屑 四类齐备，有验收脚本

---

## 一、为什么要做

搜索引擎看不懂"这是一个 Excel 模板"和"这是一个软件"的区别——除非你用 schema.org 告诉它。
有了结构化数据：

- 搜索结果可能出现富摘要（软件显示版本/平台，课程显示提供方）
- 搜索引擎能理解站点有站内搜索（sitelinks searchbox）
- 面包屑可以从结果页直接显示层级，而不是一串裸 URL

之前项目里只有**详情页手写的一小块**，而且字段不全（没有 url、没有 identifier、dateModified 是字符串）。
这轮把它做成统一的三层：

| 页面 | 输出 |
|---|---|
| 首页 | `WebSite` + `SearchAction`（站内搜索入口） |
| 分类页 / 标签页 | `CollectionPage` + `ItemList` + `BreadcrumbList` |
| 详情页 | `SoftwareApplication` / `CreativeWork` / `Course` / `Book` + `BreadcrumbList` |

---

## 二、实现

```
src/lib/seo.ts              纯函数：websiteJsonLd / breadcrumbJsonLd / collectionJsonLd / resourceJsonLd
src/components/seo/json-ld.tsx   注入组件（自动转义 <）
```

**类型按 kind 映射**，而不是一律 `SoftwareApplication`：

```ts
software → SoftwareApplication   （带 operatingSystem + offers）
course   → Course                （带 provider）
ebook    → Book
其余     → CreativeWork          （模板 / 素材 / 字体 / 图标）
```

**刻意不做的事**：不加 `aggregateRating`。我们没有评分体系，凭空写 `4.8 / 128 人评价`
属于典型的结构化数据作弊，被识别会整站降权。单测里有一条专门守着这个：

```ts
test("详情页：不编造评分（没有 aggregateRating）", …)
```

**绝对地址**：所有 `url` / `image` / 面包屑 `item` 都过 `abs()`（基于 `SITE_URL`），
schema.org 不接受相对路径。

---

## 三、验收

单测 7 条（`tests/seo.test.ts`）+ 页面级脚本（`scripts/test-seo.mjs`）：

```
home     → 1 block: WebSite（含 SearchAction）
category → 2 blocks: CollectionPage + BreadcrumbList
detail   → 2 blocks: CreativeWork + BreadcrumbList（模板类）
tag      → 2 blocks: CollectionPage + BreadcrumbList
✓ 结构化数据通过
```

脚本检查的不只是"有没有"，还包括：

- 面包屑 `position` 必须从 1 连续递增
- 所有 `item` / `url` / `image` 必须是 `http(s)://` 开头
- 详情页必须有 `name` + `identifier`（我们用自己的 `XM-2026-0001` 编号）
- 不允许出现 `aggregateRating`

## 四、这轮发现的问题：新旧两份 JSON-LD 打架

加完新代码后，验收脚本报详情页有 **3 个 block**：

```
SoftwareApplication  ← 旧的（M1 手写，字段不全）
CreativeWork         ← 新的（按 kind 映射）
BreadcrumbList       ← 新的
```

同一个实体被描述成两种类型、字段还不一致，解析器只会挑一个，等于白写。
排查发现是 M1 阶段在 `page.tsx` 里内联的 `<script>` 没删——之前 grep 只搜了三个文件，漏了。

**教训**：结构化数据是"要么没有、要么唯一"，加新的一定要删旧的。
现在由 `test-seo.mjs` 守着：详情页正文类型必须恰好 1 个。
