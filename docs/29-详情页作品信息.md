## 2. 为什么这么设计

**为什么删「本站直链」而不是删数据？**
`provider='self'` 的链接有两类用途：Galgame / MOD 里它只是「回源站看看有没有更新」的重复入口；
GitHub 开源项目里它就是仓库地址（唯一入口）。所以按「有没有别的链接」判断：
有网盘就隐藏，只剩一条（GitHub）就保留。80 个开源项目不会因此变成「暂无链接」。

**为什么用 `meta_json` 而不是加一堆列？**
来源站字段各不相同（TouchGal 有会社/发售/VNDB/Bangumi，改天接 DLsite 又是另一套）。
一张 JSON 字段 + 一个归一函数，新增来源时只改抓取脚本，不动表结构、不动迁移。

**为什么抓取在本地、导入在服务器？**
TouchGal 是 Cloudflare + 客户端渲染，服务器（Ubuntu 轻量）没有 Chromium。沿用之前的做法：
本地用真实浏览器抓 → 导出 `data/import/touchgal-meta.json` → scp 上传 → 服务器纯 Node 写入。

## 3. 抓到的字段（示例：魔法使之夜）

```json
{
  "source": "TouchGal",
  "originalTitle": "魔法使之夜",
  "aliases": ["魔法使いの夜", "Mahoutsukai no Yoru", "Witch on the Holy Night", "마법사의 밤", "Mahoyo"],
  "company": "TYPE-MOON",
  "releaseDate": "2012-04-12",
  "resourceTypes": ["游戏本体", "存档", "图片CG", "破解补丁"],
  "platforms": ["Windows", "Android", "iOS"],
  "languages": ["简体中文", "日本語", "其它"],
  "rating": "9.5",
  "views": "36.3w",
  "officialUrl": "https://store.steampowered.com/app/2052410/_/"
}
```

字段映射到「作品信息」表的顺序：原名（与站内标题相同则省略）→ 别名 → 会社 → 发售 → 形态 → 语言 → 评分 → 浏览 → 收藏 → VNDB → Bangumi → 官网 → 标签。

同时 `summary` 改成介绍首句（≤120 字，用于卡片与 OG），`content_md` 换成真实游戏介绍（按空行分段，详情页原样式直接可读）。

## 6. 已知边界

- 抓取只覆盖 `source_url LIKE '%touchgal%'` 的记录（449 条）；MODS / 开源项目暂无结构信息，页面会自动隐藏「作品信息」表。
- 详情页仍是 `ƒ Dynamic`（因为要读登录态），每次请求都查库；这是既有行为，与本次改动无关。
- `meta_json` 目前只能由脚本写入，后台表单未提供编辑入口（后续要做时，加一个 textarea 即可，解析复用 `parseResourceMeta`）。
- 网盘标题本身是分享者随手写的，仍可能出现「【KRKR➕TY模拟器➕PC】…」这类噪声；截断只解决布局，不解决语义。
