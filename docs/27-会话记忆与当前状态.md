## 2. 各阶段的关键决策（为什么这么做）

### ① 规划期
- 参考了 urldb、panhub、frontend-nav、Cloudreve、Alist、maccms10 等 10 个开源项目，结论是**自建单体**而不是套模板。
- 用户明确「后期很多地方会改」→ 一切**可配置化**：文案全在 `src/content/site.ts`，颜色全在 `globals.css` 的 CSS 变量。

### ②–③ 工程期
- `better-sqlite3` 在 Node 24 上 `Assertion failed: (env) != nullptr` 直接崩 → 运行时换 `node:sqlite`。
- `drizzle-kit push` 把 FTS5 影子表 DROP 了 → 改**显式 SQL 迁移**（`src/db/sql/` + `scripts/migrate.mjs`）。
- `next/og` 需要打包 CJK 字体 → 分享图改 **sharp + 手写 SVG**。
- 阿里云香港轻量 + systemd(`www-data`:3100) + Caddy 自动 HTTPS，三个 host：`ttals.com`、`admin.ttals.com`、`www`→301。

### ④ 视觉改版
- 旧风格"卡片目录柜"（墨绿黑 `#0B1310` + 黄铜 `#D3A94F` + 衬线）整站废弃。
- 新风格：白底、`#2563eb` 蓝、14px 圆角、极简扁平；**后台不跟随**，单独 `.admin-scope`（灰 `#f4f4f5` + 石墨 `#18181b` + 4px 圆角、无阴影）。
- 教训：改完 tokens 后用户"看不到变化"，根因是 **构建与运行中的服务抢 `.next` 目录**导致 CSS chunk 500 → deploy 改成先停服务再删 `.next/server|static`。

### ⑤ 后台与注册
- 后台走**子域名**而不是 `/admin` 路径，登录页也独立（`admin.ttals.com/login`），前台不出现任何后台入口。
- 登出"点了没反应"两层根因：① middleware matcher 包住了 `/api/*`，把清除指令又写回 cookie；② `__Secure-` 前缀的 cookie 必须带 `Secure` 才删得掉。
- 注册用 QQ SMTP 验证码；`SMTP_PASS` 是**授权码**不是 QQ 密码。

### ⑥ 用户体系
- Supabase 导出的 bcrypt 哈希直接搬过来，`bcryptjs` 在 Next 打包后 `compareSync` 变 undefined（被 try/catch 吞掉 → 所有密码都错）→ `bcryptNS.default ?? bcryptNS` 修好；登录成功自动 rehash 成 scrypt。
- 迁移数据的坑：CSV 里 `qq.con` 不是笔误，是同一个人注册了两次（`.con` 收不到信）；修正域名后撞车，导入器保留最早注册的那条 → **33 条入库**。
- 游客态收敛：收藏、下载、复制全部**强制登录**，且由服务端决定按钮形态（游客 HTML 里根本没有复制逻辑，绕不过去）。
- 头像不显示：上传 URL 多拼一层 `/uploads`（`/files` 的根就是 `data/uploads`）；顶部还读 JWT 旧快照。
