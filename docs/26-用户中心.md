# 26 · 用户中心（/me）

> 日期：2026-11-05 ｜ 状态：已完成，本地 e2e 通过；设置页刻意保持最小

---

## 一、页面结构

`/me` 一个页面，三个 tab（`?tab=`）：

| tab | 内容 |
|---|---|
| 收藏（默认） | 卡片栅格，未登录时显示本机 cookie 收藏 |
| 投稿 | 列表 + 状态（待审核 / 已通过 / 未通过） |
| 设置 | 昵称、密码 —— **只有这两项** |

`/favorites` 保留为 301 跳转（`/me?tab=favorites`），导航里的「收藏」改成「我的」。

---

## 二、头像

- 入口：`/me` 头部的「更换头像」
- 上传：`POST /api/avatar`（需登录），最大 4MB
- 处理：sharp `rotate()` 按 EXIF 摆正 → `resize(256,256, cover, attention)` → WebP q86
- 存储：`data/uploads/avatars/{userId}.webp`，文件名固定所以天然覆盖旧图
- 展示：URL 带 `?v=时间戳` 破缓存；没头像时显示昵称首字

失败提示都会落到前端（格式不支持 / 太大 / 处理失败），不会静默失败。

---

## 三、昵称与密码

**昵称**：24 字上限，服务端 trim，改完 `revalidatePath("/me")`。

**密码**：
- 有密码：要验旧密码
- 没密码（验证码注册 / Supabase 迁来）：直接设置，等同「设置密码」
- 强度：≥8 位且含字母+数字
- 保存后 `token_version + 1` → 其它设备会话失效，本人跳 `/login?changed=1`

---

## 四、设置页为什么这么少

用户明确要求：**设置项不要多，以后再加**。所以现在只有"改名"和"改密码"两件事，都属于高频且必须有。

以下都**暂不做**，等有需要再说：

| 待做项 | 为什么现在不做 |
|---|---|
| 邮箱换绑 | 需要旧邮箱 + 新邮箱双向验证，属于低频操作 |
| 通知偏好 | 站内目前没有通知系统，做了也没东西可选 |
| 退出所有设备 | `token_version` 机制已具备，只是没暴露按钮 |
| 删除账号 | 涉及数据处置策略（收藏、投稿怎么算），需要先定规则 |
| 头像裁剪框 | 现在是自动 `attention` 裁剪，够用 |

要做的时候，都是在这一个页面上加卡片，不需要动数据结构。

## 五、查询层的坑

`resources.platforms` 在库里是 **JSON 字符串**，而 `ResourceCard` 要 `string[]`。
`/me` 复用了资源卡片，如果直接把 SQL 结果丢进去，会在渲染时报：

```
TypeError: (a.platforms ?? []).slice.map is not a function
```

所以查询集中在 `src/lib/queries/user.ts`，统一 `JSON.parse` + 兜底逗号分隔，并把 `isFeatured` 转成 boolean。页面层拿到的就是干净的卡片数据。
