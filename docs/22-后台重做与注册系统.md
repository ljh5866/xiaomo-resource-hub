# 22 · 后台重做 + 用户注册系统

> 日期：2026-11-04 ｜ 状态：后台换成独立的全屏控制台；注册/登录/封禁闭环打通

---

## 一、为什么改

三个诉求：

1. **后台要更简洁、好管理** —— 原来是一排横向按钮，页面一多就挤成一团
2. **后台风格要和前台区分** —— 前台是白底蓝调的展示站，后台再做一套一样的没有意义
3. **前台不能出现后台入口** —— 之前顶栏有个「后台」按钮，等于告诉所有人门在哪

## 二、后台：换了一套视觉语言

不是"前台换个色"，是**刻意做成另一个产品**：

| 维度 | 前台 | 后台 |
|---|---|---|
| 底色 | 纯白 | 灰 #f4f4f5 |
| 强调色 | 蓝 #2563eb | 石墨黑 #18181b |
| 圆角 | 14px | 4px |
| 阴影 | 有 | 无 |
| 布局 | 顶部导航 + 居中内容 | 左侧栏 + 全屏工作区 |
| 字号 | 16px 正文 | 14px，表格 13px |

实现方式是给后台套一个 `.admin-scope`，在里面覆盖同一批 CSS token：

```css
.admin-scope {
  --bg: #f4f4f5;  --surface: #ffffff;
  --accent: #18181b;  --on-accent: #ffffff;
  --radius-card: 4px;  --card-shadow: none;
}
```

因为全站都用语义 token（`bg-surface` / `text-ink` / `border-line`），**一处覆盖，所有后台页面自动变灰变方**，不用逐个改组件。

### 导航按场景分组

原来 7 个平铺按钮，现在三组：

```
内容    概览 / 资源 / 分类与标签
运营    投稿 / 举报 / 链接巡检
系统    批量导入 / 用户
```

### 前台彻底不含后台入口

- 删掉了顶栏的「后台」链接
- 后台页面加 `robots: { index: false, follow: false }`
- `robots.txt` 里 `Disallow` 后台路径
- 想更进一步：设 `ADMIN_PATH=console-x7k2`，middleware 会把 `/console-x7k2/*` 内部重写到 `/admin/*`，**地址栏不变，前台没有任何地方链接它**

```ini
ADMIN_PATH=console-x7k2
```

### 顺手修掉的一个结构问题

改完发现后台顶部还压着前台的 header —— 因为根 layout 无条件渲染了 Header/Footer。
用 Next 的 Route Group 拆开：

```
src/app/layout.tsx          只放 html/body/AuthProvider
src/app/(front)/layout.tsx  Header + Footer（前台所有页面）
src/app/admin/layout.tsx    全屏侧栏（后台）
```

路由 URL 完全不变（`(front)` 是分组，不进路径）。

## 三、用户注册系统

### 数据

迁移 `005_user_status.sql`：给 `users` 加 `status`（active / pending / banned）+ 索引。

### 注册

`/register`：邮箱 + 昵称（选填）+ 密码 + 确认密码。

服务端（Server Action）做了这些校验：

| 检查 | 规则 |
|---|---|
| 邮箱格式 | 简单正则，不追求 RFC 完整 |
| 密码强度 | ≥8 位，且必须同时含字母和数字 |
| 两次一致 | 客户端 + 服务端都校验 |
| 重复邮箱 | 先查再插，`UNIQUE` 冲突兜底 |
| 防刷 | 同 IP 每小时 5 次、同邮箱每小时 3 次 |
| 开关 | `ALLOW_REGISTRATION=false` 时直接拒绝 |

注册成功后跳 `/login?registered=1&email=...`，邮箱预填，少打一次字。

### 登录

`authorize()` 里加了状态判断：

```ts
if ((user.status ?? "active") !== "active") return null;
```

所以 **pending（待审核）和 banned（封禁）都登不进来**。

### 后台「用户」页

`/admin/users`：

- 列表：邮箱 / 昵称 / 角色 / 状态 / 收藏数 / 注册时间
- 筛选：全部 / 正常 / 待审核 / 已封禁 + 邮箱昵称搜索
- 操作：封禁（或解封）、设为管理员（或降级）、重置密码

三条安全约束写在了动作里：

1. 不能改自己的状态和角色
2. 不能把最后一个管理员降级或封掉
3. 任何变更都会 `token_version + 1` —— **旧会话立刻失效**

## 四、这轮踩的坑

### 1. `"use server"` 文件只能导出 async 函数

在 `auth/register.ts` 里顺手导出了一个同步的 `registrationOpen()`，构建直接报：

```
Error: Server Actions must be async functions.
```

修法：把开关函数挪到普通模块 `src/lib/flags.ts`。**规则**：`"use server"` 文件里每个导出都必须是 async。

### 2. 普通用户能打开 /admin

middleware 原来只判断"有没有登录"，不判断角色 —— 注册用户直接访问 `/admin` 拿到了 200。
修成两道：

- middleware：`req.auth.user.role !== "admin"` → 重定向回首页（路径存在与否不暴露）
- 后台 layout：`requireAdmin()` 再查一次库（角色可能刚被降级，JWT 里还是旧的）

### 3. 路由分组后旧的 `.next/types` 报错

移动目录后 `tsc` 报"找不到 src/app/go/[id]/route.js" —— 那是 Next 生成的路由类型文件还指着旧路径。
`rm -rf .next && pnpm build` 重新生成即可。**这不是代码错，是构建缓存错。**
