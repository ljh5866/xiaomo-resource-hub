# 09 · 部署与运维手册

> 目标：一台 2C4G 的 VPS，从零到可访问，30 分钟内完成；日常更新一条命令。
> 本文所有命令都在 Ubuntu 24.04 + Node 24 + pnpm 上验证过逻辑（Windows 本地只跑开发态）。

---

## 一、上线前必须改的三件事

| # | 项 | 怎么改 |
|---|---|---|
| 1 | `AUTH_SECRET` | `openssl rand -hex 32` 生成，别用示例值 |
| 2 | 管理员密码 | `pnpm user:add admin@你的域名 <强密码> --admin`，初始账号建议删掉 |
| 3 | `SITE_URL` | 换成真实域名（影响 sitemap / OG / 绝对链接） |

`.env` 最终长这样：

```ini
SITE_URL=https://example.com
DATABASE_URL=/var/www/xiaomo/data/app.db
AUTH_SECRET=<32 字节随机串>
```

## 二、首次部署

```bash
# 1. 系统依赖
apt update && apt install -y curl git build-essential
curl -fsSL https://deb.nodesource.com/setup_24.x | bash - && apt install -y nodejs
corepack enable && corepack prepare pnpm@10 --activate
apt install -y debian-keyring debian-archive-keyring apt-transport-https
curl -1sLf https://dl.cloudsmith.io/public/caddy/stable/gpg.key | gpg --dearmor -o /usr/share/keyrings/caddy-stable-archive-keyring.gpg
curl -1sLf https://dl.cloudsmith.io/public/caddy/stable/debian.deb.txt | tee /etc/apt/sources.list.d/caddy-stable.list
apt update && apt install -y caddy

# 2. 代码
mkdir -p /var/www && cd /var/www
git clone <你的仓库> xiaomo && cd xiaomo
pnpm install --frozen-lockfile

# 3. 环境变量
cp .env.example .env && nano .env     # 按上一节填

# 4. 数据库 + 种子 + 封面 + 管理员
pnpm db:migrate
pnpm db:seed          # 可选：想从空白开始就跳过
pnpm covers:gen       # 可选：演示封面
pnpm user:add admin@example.com '<强密码>' --admin

# 5. 构建
pnpm build

# 6. 权限（服务以 www-data 跑）
chown -R www-data:www-data /var/www/xiaomo/data

# 7. systemd
cp deploy/xiaomo.service /etc/systemd/system/
cp deploy/xiaomo-maintenance.{service,timer} /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now xiaomo
systemctl enable --now xiaomo-maintenance.timer

# 8. Caddy
cp deploy/Caddyfile /etc/caddy/Caddyfile
sed -i 's/example.com/你的域名/' /etc/caddy/Caddyfile
systemctl reload caddy

# 9. 验证
curl -s https://你的域名/api/health
```

期望输出：

```json
{"ok":true,"app":"xiaomo","db":{"latencyMs":3,"published":24},"uptimeSec":9,"memoryMB":108}
```

## 三、日常更新

```bash
bash deploy/deploy.sh
```

它按顺序做六件事，任何一步失败就停：

```
备份 → git pull → pnpm install → db:migrate → build → systemctl restart → health check
```

**回滚**：`git reset --hard <上一个 tag>` 后重跑 `deploy.sh`；数据库用备份目录里的 `app.db` 覆盖（见下一节）。

## 四、备份与恢复

```bash
pnpm backup                # 写 data/backups/<时间戳>/{app.db, uploads/}
node scripts/backup.mjs --keep 14
```

- 数据库用 `VACUUM INTO` 做一致性快照（WAL 模式下也安全），不是直接拷文件
- 封面目录整体复制，保留结构
- 默认保留最近 7 份，`--keep` 可调
- 定时任务里已挂：每天 03:20 巡检 + 备份 + 清孤儿图

**恢复演练（每季度做一次）**：

```bash
systemctl stop xiaomo
cp data/backups/2026-11-03T08-19-13/app.db data/app.db
rm -rf data/uploads && cp -r data/backups/2026-11-03T08-19-13/uploads data/uploads
systemctl start xiaomo
curl -s localhost:3100/api/health
```

> 没演练过的备份等于没有备份。

## 五、定时任务

`deploy/xiaomo-maintenance.service` 一次跑三件事：

```ini
ExecStart=/usr/bin/pnpm links:check
ExecStartPost=/usr/bin/node scripts/backup.mjs --keep 14
ExecStartPost=/usr/bin/pnpm covers:gc --force
```

`deploy/xiaomo-maintenance.timer` 每天 03:20（带 5 分钟随机延迟，避免整点挤）。

看执行结果：

```bash
systemctl list-timers xiaomo-maintenance.timer
journalctl -u xiaomo-maintenance -n 50 --no-pager
```

## 六、监控

| 项 | 做法 |
|---|---|
| 存活 | Caddy `health_uri /api/health` 每 30s；UptimeRobot 5 分钟一次 |
| 进程 | `systemctl status xiaomo`；`MemoryMax=1G` 兜底重启 |
| 日志 | `journalctl -u xiaomo -f`（访问日志在 `/var/log/caddy/`） |
| 业务 | `/admin` 看板：死链率、搜索索引条数、本周更新 |

**告警阈值建议**：死链率 > 10%、健康检查连续 3 次失败、内存 > 800MB。

## 七、上线检查清单

- [ ] `AUTH_SECRET` 已换成随机值，示例账号已删除
- [ ] `SITE_URL` 是真实域名，`/sitemap.xml` 里全是 https 链接
- [ ] `/admin` 未登录访问返回 302 到 `/login`
- [ ] `/api/upload` 未登录返回 401
- [ ] 首页/详情页 LCP < 2.5s（PageSpeed Insights 实测）
- [ ] 提交 sitemap 到 Search Console / Bing
- [ ] 备份跑通一次，且**恢复演练过一次**
- [ ] 定时任务 `systemctl list-timers` 能看到下一次执行时间
- [ ] 域名备案（若放国内）

## 八、已知的运维债

| # | 债 | 影响 |
|---|---|---|
| 1 | 限流是进程内内存 | 多实例部署前要换 Redis，否则限流各算各的 |
| 2 | JWT 无黑名单 | 改密码后旧会话仍有效到 30 天过期 |
| 3 | SQLite 单写 | 并发写只有个位数，资源量破万前够用；破了换 Postgres |
| 4 | 封面单尺寸 | 详情页放大略糊，可加 1600w |
| 5 | 无 CI | 现在靠本地 `pnpm build && pnpm test`，建议接 GitHub Actions |
