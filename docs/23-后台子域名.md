# 23 · 后台挂在子域名

> 日期：2026-11-04 ｜ 状态：`admin.ttals.com` 已签发证书并分流成功

---

## 一、为什么要子域名

用 `/admin` 路径有三件事做不到：

1. **彻底隔离** —— 主域任何路径都不会命中后台代码，连"猜路径"都不成立
2. **策略分开** —— 后台要 `no-store`、要 `noindex`、要禁止被 iframe，前台要长缓存。同域下用路径前缀区分虽然也能写，但容易漏
3. **以后好加防护** —— 想给后台加 IP 白名单 / Basic Auth，在 Caddy 里给 `admin.` 那个站点块加几行就行，不用动 Next 代码

---

## 二、怎么开

### 1. DNS

```
类型 A   主机 admin   值 43.103.48.5   TTL 600
```

### 2. 环境变量

```ini
ADMIN_HOST=admin.ttals.com
SITE_HOST=ttals.com
```

不设 `ADMIN_HOST` 就退回路径模式（`/admin`），行为不变。

### 3. Caddyfile

`deploy/Caddyfile.ttals.com` 现在是三个站点块：

| 站点 | 作用 |
|---|---|
| `ttals.com` | 前台，静态资源长缓存 |
| `admin.ttals.com` | 后台，`no-store` + `X-Robots-Tag: noindex` + `X-Frame-Options: DENY` |
| `www.ttals.com` | 301 到主域 |

### 4. 生效

```bash
sudo cp /var/www/xiaomo/deploy/Caddyfile.ttals.com /etc/caddy/Caddyfile
sudo systemctl restart caddy      # 首次建议 restart，reload 有时跟不上新域名
```

## 三、路由怎么分流

决策逻辑抽成了纯函数 `src/lib/admin/route-map.ts`，middleware 只负责翻译成响应：

```ts
decideAdminRoute({ pathname, host, authenticated, role, adminHost })
  → { kind: "pass" }
  | { kind: "redirect", to }
  | { kind: "rewrite", pathname }
```

| 请求 | 结果 |
|---|---|
| `admin.ttals.com/` | 内部重写到 `/admin` |
| `admin.ttals.com/users` | 内部重写到 `/admin/users` |
| `admin.ttals.com/admin/users` | 原样放行（页面里的绝对链接不会再被加前缀） |
| `admin.ttals.com/login` | 放行（否则登录页也要求登录 → 死循环） |
| `admin.ttals.com/*` 未登录 | 302 → `/login?next=…` |
| `admin.ttals.com/*` 普通用户 | 302 → `https://ttals.com/` |
| `ttals.com/admin` | 307 → `https://admin.ttals.com/` |
| `ttals.com/c/games` | 不受影响 |

15 条单测覆盖以上全部分支（`tests/admin-routing.test.ts`）——**不用起服务、不用真域名就能验**。

## 四、踩过的坑

### 1. `reload` 静默失败

改完 Caddyfile 后 `systemctl reload caddy` 返回 0，但新域名不生效：

```
grep admin /etc/caddy/Caddyfile     → 有，第 53 行
caddy validate --config …           → Valid configuration
curl https://admin.ttals.com/       → SSL/TLS 握手失败
```

`caddy validate` 只校验语法，不代表进程已加载。改成 `systemctl restart caddy` 后立刻正常。

> 经验：**首次加新域名用 restart，日常改站点用 reload**。

### 2. 证书签发需要几秒到几十秒

`restart` 之后立刻 curl 会失败——Caddy 还没走完 ACME 流程。至少要等 15–30 秒，或者盯日志：

```bash
sudo journalctl -u caddy -f | grep -i "admin.ttals.com"
```

看到 `certificate obtained successfully` 才算好了。

### 3. 双前缀陷阱

子域名下页面里写的是 `/admin/users` 这种绝对路径。如果中间件无脑加前缀，会变成 `/admin/admin/users` → 404。
所以判断顺序必须是"**已经是 /admin 开头就原样放行**"。

## 五、验收

```bash
curl -sI https://admin.ttals.com/ | head -3        # 307 → /login?next=%2F
curl -sI https://admin.ttals.com/login | head -1   # 200
curl -sI https://ttals.com/admin | head -3         # 307 → https://admin.ttals.com/
curl -sI https://ttals.com/ | head -1              # 200
```

证书检查：

```bash
echo | openssl s_client -connect admin.ttals.com:443 -servername admin.ttals.com 2>/dev/null | openssl x509 -noout -subject -issuer -dates
# subject=CN=admin.ttals.com  issuer=Let's Encrypt  有效期 90 天，Caddy 自动续
```
