# 21 · 上线操作单（阿里云香港 43.103.48.5）

> 服务器：公网 `43.103.48.5` · 内网 `172.21.58.136` · Ubuntu 24.04 · 2C2G · 域名 `ttals.com`
> 代码仓库：`https://github.com/ljh5866/xiaomo-resource-hub`
>
> 当前实测：**22 端口通，80 / 443 不通** ← 第一件事就是去控制台放行

---

## 第 0 步 · 放行端口（先做，否则后面白忙）

轻量控制台 → 服务器详情 → **防火墙** → 添加规则：

| 协议 | 端口 | 用途 |
|---|---|---|
| TCP | 22 | SSH（已通） |
| TCP | 80 | HTTP + 证书验证（**必须**） |
| TCP | 443 | HTTPS |

放行后本地验证：

```bash
# Windows PowerShell
foreach ($p in 80,443) { Test-NetConnection 43.103.48.5 -Port $p }
```

## 第 1 步 · 把代码推上 GitHub

在你的 Windows 机器上（`D:\小莫资源站`）：

```bash
# 1. 先在 GitHub 网页上建一个空仓库：xiaomo-resource-hub（Private 即可，不要勾 README）
# 2. 关联并推送
git remote add origin https://github.com/ljh5866/xiaomo-resource-hub.git
git branch -M main
git push -u origin main
```

推送前确认敏感文件没进去（`.gitignore` 已排除，这里再核一次）：

```bash
git status --short          # 应该是干净的
git ls-files | findstr /i ".env app.db"    # 应该只看到 .env.example
```

> GitHub 现在不支持密码推送，需要 Personal Access Token：
> Settings → Developer settings → Personal access tokens → Fine-grained tokens，
> 勾 `Contents: Read and write`，推送时密码处粘贴 token。

输出最后会打印 node / pnpm / caddy 版本与内存，确认都是预期值再往下。

## 第 3 步 · 拉代码 + 配置

```bash
cd /var/www/xiaomo
git clone https://github.com/ljh5866/xiaomo-resource-hub.git .

cp .env.example .env
openssl rand -hex 32          # 复制输出的 64 位字符串
nano .env
```

`.env` 填成这样（**没有域名时** `SITE_URL` 先写 IP）：

```ini
SITE_URL=https://ttals.com
DATABASE_URL=/var/www/xiaomo/data/app.db
AUTH_SECRET=<上一步 openssl 生成的 64 位串>
```

> 有域名后把 `SITE_URL` 改成 `https://你的域名` 并重启服务即可。

```bash
pnpm install --frozen-lockfile
pnpm db:migrate
pnpm user:add 你的邮箱 '强密码' --admin    # 这就是后台登录账号
pnpm build                                 # 2C2G 约 40–60 秒
```

## 第 4 步 · 起服务 + 反代

```bash
cp deploy/xiaomo.service /etc/systemd/system/
cp deploy/xiaomo-maintenance.service /etc/systemd/system/
cp deploy/xiaomo-maintenance.timer /etc/systemd/system/
systemctl daemon-reload

chown -R www-data:www-data /var/www/xiaomo/data
systemctl enable --now xiaomo
systemctl enable --now xiaomo-maintenance.timer

systemctl status xiaomo --no-pager | head -5
curl -s http://127.0.0.1:3100/api/health
```

看到 `{"ok":true,...}` 说明服务本身没问题，接下来只管反代。

反代二选一：

```bash
# ttals.com 已经解析到本机，直接用生产配置
cp deploy/Caddyfile.ttals.com /etc/caddy/Caddyfile
```

```bash
systemctl reload caddy
journalctl -u caddy -n 30 --no-pager    # 有域名时这里能看到证书申请过程
```

## 第 5 步 · 验收（逐条打勾）

## 第 6 步 · 拿到域名之后

1. 阿里云 DNS → 添加 A 记录：`@` 与 `www` 都指向 `43.103.48.5`，TTL 600
2. 等解析生效：`nslookup 你的域名`
3. 服务器上：

```bash
cp deploy/Caddyfile.ttals.com /etc/caddy/Caddyfile
systemctl reload caddy

nano /var/www/xiaomo/.env           # SITE_URL 改成 https://你的域名
systemctl restart xiaomo

curl -fsS https://你的域名/api/health
```

4. 回后台把封面上传、导入几条真实资源，跑一次 `pnpm links:check`。

> 香港属境外地域，**不需要 ICP 备案**。但如果之后要接国内 CDN，CDN 域名需要备案。

## 附：常见卡点对照表

| 现象 | 原因 | 处理 |
|---|---|---|
| `curl http://IP` 一直转圈 | 控制台防火墙没放 80 | 放行 TCP 80 |
| Caddy 日志 `tls: no certificate` | 域名解析还没生效，或 80 被封 | `nslookup` 确认解析；确认 80 放行 |
| 页面 502 | 服务没起来 | `systemctl status xiaomo`；`journalctl -u xiaomo -n 50` |
| 上传封面报 500 | `data/uploads` 权限不对 | `chown -R www-data:www-data /var/www/xiaomo/data` |
| 构建到一半 `Killed` | 内存不够 | `free -h`；2G 机型应正常，否则加 swap |
| 后台登录一直"邮箱或密码不对" | 账号没建 / 密码错 | `pnpm user:add 邮箱 密码 --admin` 重建 |
