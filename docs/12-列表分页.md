# 12 · 列表分页与「加载更多」

> 日期：2026-11-03 ｜ 状态：分类页 24/页、更新页 12/页，首屏静态、后续按需加载

---

## 一、为什么不用 `?page=2`

最直觉的做法是 `/c/template?page=2`，但它会让**每个列表页从静态变成动态**（页面要读 `searchParams`），
SSG/ISR 全部失效，CDN 也缓存不住。

所以分了两层：

| 层 | 谁做 | 说明 |
|---|---|---|
| 首屏 | 服务端静态（SSG/ISR） | 分类页 24 条、更新页 12 条，构建期就渲染好 |
| 后续 | `GET /api/resources?offset=24&limit=12` | 客户端点击「加载更多」时拉 |

代价：列表页的深层条目对爬虫不可见。可接受——真正需要被索引的是**详情页**，
它们全部在 sitemap 里，且本身是 SSG。

## 二、实现

```
src/app/c/[category]/page.tsx    服务端取 24 条 + COUNT(*)
src/app/updates/page.tsx         服务端取 12 条 + COUNT(*)
        ↓ props
src/components/resource/resource-feed.tsx   （客户端）
   ├ initialItems / initialTotal / nextOffset
   ├ 点按钮 → fetch /api/resources?category=…&offset=…&limit=…
   └ 追加去重（按 code）
src/app/api/resources/route.ts   offset/limit 切片，返回 total + nextOffset
src/lib/queries.ts               listResources({offset}) + countResources()
```

接口约定：

```json
GET /api/resources?category=template&offset=24&limit=12
{
  "ok": true,
  "total": 33,
  "nextOffset": null,          // 没有下一页就是 null
  "items": [ { "code": "XM-2026-0034", "updatedAt": 1762150000000, … } ]
}
```

`updatedAt` 序列化成**毫秒数**（不是 ISO 字符串），客户端直接 `new Date(ms)`，省一次解析。

## 三、抓到的两个问题

### 1. CLS 从 0.0001 飙到 0.148（性能门禁拦下）

加了 Suspense 后，fallback 是 3 张骨架卡，解析完成后变成 24 张卡 —— 高度差直接把整页顶下去。

修法：让 fallback 和真实结构**同高**。

```tsx
fallback={
  <>
    <CategoryChips platformKeys={keys} active="" />   {/* 与客户端同一组件，只是没有高亮 */}
    <CardGridSkeleton count={9} />
    <div>已显示 … / 共 … 项 + 按钮占位</div>
  </>
}
```

改完 CLS 回到 0.0001。**这正是上一轮加性能门禁的价值**：肉眼完全看不出来，指标直接红。

### 2. 压测数据标题重复

`seed:bulk --count 48` 再加 `--count 152` 时，两次都从 1 开始编号，页面出现两条「分页压测资源 022」
（编码不同、标题相同）。修法：从已有压测条数续号。

## 四、压测数据怎么造

```bash
pnpm seed:bulk --count 200   # 标题形如「分页压测资源 022」，一眼能认出是假数据
pnpm seed:bulk --clean       # 全部清掉（slugs 以 bulk- 开头）
```

它会轮转分类/平台/网盘，并给每条塞两个链接，顺便把搜索索引也重建。
用途：验证分页、列表渲染性能、以及内容上到 200 条之后的真实观感。

> 注意：批量造数之后**需要重新构建**（`pnpm build`），否则分类页仍是构建期的旧数据——
> 这些页面是 SSG，默认 10 分钟 ISR。后台改一条会 `revalidatePath`，但脚本直接改库不会。

## 六、还没做的

| # | 项 | 说明 |
|---|---|---|
| 1 | 搜索页分页 | 搜索是动态页，暂时 40 条封顶；后面按同样模式加 |
| 2 | 无限滚动 | 现在的按钮式更可控（也更好做无障碍）；不做自动加载 |
| 3 | 分页 URL | 深层条目没有独立 URL，想被索引得改路径段（`/c/x/page/2`） |
| 4 | 排序切换 | 现在固定「精选优先 → 发布时间」；要加排序就得再把参数搬进 API |
